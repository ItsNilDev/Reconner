# Changes and scan scope audit

Reviewed Reconner at `0f8a906`. Findings only.

## Out-of-scope enforcement

Both breadth and deep web scans drop matching `exclude_scope` hosts from the initial HTTP probe list. In breadth, the probe runs before the linked program eligibility check. In deep scans, later phases can use saved services and endpoint seeds. These paths leave gaps in the exclusion boundary. See [HTTP probe filtering](../internal/scanner/http.go#L76), [watch scope landing](../internal/scanner/http.go#L256), and [deep fingerprinting](../internal/scanner/http.go#L323).

1. **High · Deep scans can revisit a previously probed host after it is excluded.** The HTTP phase leaves old service rows in place. Deep fingerprinting and the monitor load those rows and check the positive host scope. A host under an approved parent can still pass that check and receive requests after being added to `exclude_scope`. Endpoint seeds are also registered before the HTTP exclusion check. See [fingerprinting](../internal/scanner/http.go#L323), [monitor service loading](../internal/scanner/monitor.go#L69), and [endpoint seeding](../internal/scheduler/scheduler.go#L1806).
2. **High · Suspending the last approved asset can put it back into both scan tiers.** When managed seeds are empty, the scheduler uses the original `targets.domain` values. Domain enumeration has a separate fallback to the same original scope when no approved domain roots remain. A project whose last approved asset was suspended can start from the asset it just lost. A remaining URL-only asset can also leave the old domain in the enumeration fallback. See [shared scan seeding](../internal/scheduler/scheduler.go#L1770) and [enumeration roots](../internal/scheduler/scheduler.go#L2558).
3. **High · Program deny rules go stale after import.** Import snapshots active program exclusions into `targets.exclude_scope`. Reconciliation suspends matching imported assets that lose eligibility, but leaves that exclusion snapshot untouched. A newly excluded descendant can still pass the HTTP probe filter under an approved parent. A newly permitted host can stay blocked by an old import rule. The watch sweep only marks `watch:scope` rows in metadata and only visits projects currently in breadth mode. See [import exclusions](../internal/bounty/catalog.go#L277), [scope reconciliation](../internal/bounty/catalog.go#L704), and [watch scope sweep](../internal/scheduler/scheduler.go#L3589).
4. **High · Positive program scope is broader in scanning than in eligibility checks.** The common scheduler host matcher accepts descendants of bare hosts as well as wildcard roots. Breadth checks the linked program's exact or wildcard eligibility only after probing. This lets a discovered descendant of an exact program asset receive a breadth HTTP request even if it cannot land as approved scope. The same generic host matcher is used by deep scan consumers. See [host matching](../internal/scanner/scan_options.go#L304), [program eligibility matching](../internal/scanner/watch_scope.go#L210), and [post-probe landing](../internal/scanner/http.go#L256).
5. **Medium · Exclusion syntax can silently change the scope of a rule.** Leading-dot suffix rules lose the dot and become exact matches. Bare `host:port` rules keep the port on storage while lookup strips it, so they miss. A full URL excludes the whole hostname, including other paths and ports. In the web probe, CIDRs are evaluated against the input host string, so a DNS name that resolves into an excluded CIDR still gets through the filter. See [exclusion parser](../internal/scanner/exclude.go#L31) and [probe inputs](../internal/scanner/http.go#L53).

## Changes feed

6. **High · Breadth status transitions are missing.** The live breadth path emits new-host events after HTTP probing and no longer calls the status snapshot and diff helpers. The API also restricts its watch source to `new_subdomain`, so older watch status rows are unavailable even with an explicit status filter or round selected. The status-filter test inserts the watch-labeled fixture into `monitoring_changes`, which leaves the real watch source untested for this behavior. See [watch phase completion](../internal/scheduler/scheduler.go#L2344), [watch feed query](../internal/api/changes_handlers.go#L112), and [status filter test](../internal/api/changes_handlers_test.go#L364).
7. **High · Ordinary deep scan plans can overwrite the status baseline.** The generic planner runs `http_probe` before `monitor`. The probe updates the saved status and title, so a later comparison can miss a transition that occurred between scans. The dedicated periodic monitor path already orders the comparison before the refresh. See [probe upsert](../internal/scanner/http.go#L385), [canonical module order](../internal/scheduler/scheduler.go#L137), and [periodic monitor ordering](../internal/scheduler/scheduler.go#L3650).
8. **Medium · The two Changes views bury the signals differently.** The global default hides all deep monitor rows, including genuine status transitions. Its before-and-after status pills only render for `status_change`, while the deep monitor emits `http_change` and `page_change`. The target Changes tab has category chips but no status-specific controls, drops event metadata and source, and renders raw before and after values. A body-only deep change can also display identical before and after values because the stored strings only contain status and title. See [global default view](../frontend/src/components/changes/changesModel.ts#L55), [status rendering](../frontend/src/components/changes/InlineChangeDiff.tsx#L20), [target data mapping](../frontend/src/pages/TargetDetail.tsx#L804), and [deep change recording](../internal/scanner/monitor.go#L191).
9. **Medium · New hosts are easy to miss or misread.** Deep enumeration records discovered names as `new_host` notifications, which the unified feed never selects. Breadth fleet rows store all member names in metadata but show one representative on the global card. Search ignores metadata, and the target tab discards that field, so a fleet member may be absent from the target tab and unfindable by its name. The global row omits the stored HTTP status and scope flag from its summary. The flag itself is per group and can be true when only some members match program scope. See [deep new-host writer](../internal/scanner/subdomain.go#L312), [feed sources](../internal/api/changes_handlers.go#L140), [search query](../internal/api/changes_handlers.go#L222), and [watch fleet grouping](../internal/scheduler/watch_changes.go#L221).
10. **Medium · Program scope changes are duplicated and hard to interpret.** An upstream addition appears as “Scope landed” while its approval can still be pending. The feed omits program and decision fields and displays raw JSON for before and after, including two different shapes for a modification. The same catalog sync can also put a “Bounty scope change” summary in the default feed alongside the detailed events. See [scope feed mapping](../internal/api/changes_handlers.go#L125), [scope event writer](../internal/bounty/catalog.go#L704), and [scope review fields](../internal/bounty/catalog.go#L608).
11. **Medium · Default filtering happens after pagination and disagrees with Mark all read.** If a page is filled by hidden monitor rows, the global feed can say “No changes recorded yet” even when later pages contain new hosts or program scope changes. The server also marks hidden monitor rows read because the default view filter lives only in the browser. See [pagination query](../internal/api/changes_handlers.go#L353), [default view and read action](../frontend/src/components/changes/ChangeLog.tsx#L421), and [server mark-all](../internal/api/changes_handlers.go#L460).

## Other issues

12. **High · A failed breadth HTTP tool can look like a healthy round.** A missing `httpx` or failed invocation can leave a nonempty input list with zero responses. The watch path logs the problem, skips the fallback, updates liveness misses, and returns success. Two such rounds can mark hosts down without successful probes. See [tool error handling](../internal/scanner/http.go#L221), [watch liveness update](../internal/scanner/http.go#L252), and [successful return](../internal/scanner/http.go#L317).
13. **Medium · A later upstream scope edit can be hidden behind an older pending review.** Pending events are deduplicated by target, asset and event type, even when their proposed state differs. Approval reads the current catalog asset while the pending event still shows the earlier version, and the saved decision fingerprint represents that earlier version. See [event deduplication](../internal/bounty/catalog.go#L758) and [approval](../internal/bounty/catalog.go#L801).

## Verification

Source review covered the global and target Changes views, the feed and read-state API, program import and reconciliation, and the shared breadth and deep scan paths. Isolated Go checks confirmed the exclusion parser behavior. In-memory SQLite checks confirmed that stored watch status rows are filtered out and that an all-suspended project produces zero approved seeds. The repository Go tests could not start because required dependencies were unavailable in the local cache and its default directory was read-only. Runtime scan behavior was assessed from source.
